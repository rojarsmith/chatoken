# Multi-Turn Conversation Memory

[English](conversation-memory.md) | [繁體中文](conversation-memory.zh-TW.md)

This final learning stage adds ChatGPT-like multi-turn session wiring.

The backend now stores a conversation in memory:

```text
conversation session
-> user message
-> assistant reply
-> next user message
-> rendered transcript
-> local model generation
```

The important lesson is that "the API remembers the messages" and "the model can attend to the messages" are related but not identical. The API can store many messages, but the model only sees the rendered transcript that fits inside the selected context budget and the model's real `context_length`.

## Web UI

Open the `Conversation` tab.

The default model is `random-tiny-byte`. It is a real PyTorch model evaluated at
send time, but it is randomly initialized and will not sound like ChatGPT. For
the local ChatGPT-like learning path, train and load `gpt2-chat-lora` from the
[Minimal GPU Chat Model](minimal-chat-model.md) stage, then use `Chat transcript`.

Use it to control:

- `System prompt`: high-level behavior instruction inserted before the turns.
- `Context format`: how stored turns are rendered before generation.
  - `Chat transcript` sends `System:`, `User:`, and `Assistant:` lines directly.
  - `Instruction request` wraps the session as one instruction asking the model to answer the latest user message.
- `History messages`: how many recent stored messages are rendered.
- `Context token budget`: logical token budget used by the conversation renderer.
- `Max new tokens`: answer length.
- `Inference mode`, `temperature`, and `top_k`: decoding behavior.

Click `Preview context` before `Send`. The preview shows:

- the exact transcript sent into the local model
- prompt tokens
- selected context budget
- model `context_length`
- messages omitted by history limit
- messages omitted by token budget
- warnings when a random model, base GPT-2 model, or mismatched prompt format is selected
- warnings when the transcript is longer than the model can actually attend to

Each stored message also shows the model that produced or was associated with that turn. This matters when you switch models inside one session: the header shows the current session setting, but older assistant messages may have been generated by a different model.

## API

Start the API:

```cmd
.venv\Scripts\activate.bat
python -m uvicorn apps.api.main:app --reload --port 8000
```

Create a conversation:

```cmd
for /f %i in ('curl -s -X POST http://127.0.0.1:8000/conversations -H "Content-Type: application/json" -d "{\"title\":\"Memory smoke test\",\"model_id\":\"random-tiny-byte\",\"system_prompt\":\"You are a concise assistant.\",\"max_history_messages\":8,\"context_token_budget\":256,\"context_format\":\"chat-transcript\",\"max_new_tokens\":16,\"temperature\":0,\"inference_mode\":\"greedy\"}" ^| python -c "import sys,json; print(json.load(sys.stdin)['conversation_id'])"') do set CONVERSATION_ID=%i
```

Send the first message:

```cmd
curl -s -X POST http://127.0.0.1:8000/conversations/%CONVERSATION_ID%/messages ^
  -H "Content-Type: application/json" ^
  -d "{\"message\":\"My name is Rojar. Please remember it.\",\"model_id\":\"random-tiny-byte\",\"system_prompt\":\"You are a concise assistant.\",\"max_history_messages\":8,\"context_token_budget\":256,\"context_format\":\"chat-transcript\",\"max_new_tokens\":16,\"temperature\":0,\"inference_mode\":\"greedy\"}"
```

Preview the second message context:

```cmd
curl -s -X POST http://127.0.0.1:8000/conversations/%CONVERSATION_ID%/context-preview ^
  -H "Content-Type: application/json" ^
  -d "{\"message\":\"What is my name?\",\"model_id\":\"random-tiny-byte\",\"system_prompt\":\"You are a concise assistant.\",\"max_history_messages\":8,\"context_token_budget\":256,\"context_format\":\"chat-transcript\",\"max_new_tokens\":16,\"temperature\":0,\"inference_mode\":\"greedy\"}"
```

Then send it:

```cmd
curl -s -X POST http://127.0.0.1:8000/conversations/%CONVERSATION_ID%/messages ^
  -H "Content-Type: application/json" ^
  -d "{\"message\":\"What is my name?\",\"model_id\":\"random-tiny-byte\",\"system_prompt\":\"You are a concise assistant.\",\"max_history_messages\":8,\"context_token_budget\":256,\"context_format\":\"chat-transcript\",\"max_new_tokens\":16,\"temperature\":0,\"inference_mode\":\"greedy\"}"
```

List conversations:

```cmd
curl -s http://127.0.0.1:8000/conversations
```

## What to Observe

1. The session stores both user and assistant messages.
2. The rendered transcript includes previous turns until history or token budget removes them.
3. `random-tiny-byte` has `context_length=64`, so even when the API transcript contains previous turns, the model may only attend to the last 64 byte tokens.
4. A loaded GPT-2 checkpoint has a much larger context window, so the same session behavior becomes more useful.
5. If a model was not trained for instruction-following, it may still fail to answer naturally even when the right context is present.

## Why Replies Can Repeat or Look Off-Topic

This is expected in the early learning stages:

- `random-tiny-byte` is randomly initialized. Its byte tokenizer decodes invalid UTF-8 as visible escape text such as `\xc0`, and greedy decoding can repeat the same highest-score byte pattern.
- downloaded `gpt2-124M` is a pretrained next-token model. It can continue text, but it was not trained as a ChatGPT-style assistant and may ignore `System/User/Assistant` structure.
- changing the model selector does not rewrite older messages. Check the model badge on each message to see which model generated that reply.
- for GPT-2 base models, neither format makes it a real chat assistant. Use `gpt2-chat-lora` with `Chat transcript` to test the local chat fine-tuning path, or use a real external chat provider for stronger behavior.

## Current Scope

Conversation sessions are in memory. Restarting the API clears them.

This is deliberate for the learning prototype. A production version would add persistent storage, user accounts, auth, rate limits, streaming conversation turns, and possibly summary-based long-term memory.
