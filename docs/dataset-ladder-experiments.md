# Dataset Ladder and Training Experiments

[English](dataset-ladder-experiments.md) | [繁體中文](dataset-ladder-experiments.zh-TW.md)

This document explains the dataset and experiment loop in LLM ABC:

```text
choose dataset -> choose base model -> train -> save checkpoint -> record experiment -> compare
```

The important rule is that dataset size and instruction following are different lessons.

- `the-verdict` is a larger raw text dataset for next-token pretraining.
- `instruction-following` is the instruction/response dataset for GPT-2 instruction SFT.

## Dataset Ladder

- `every-effort`: tiny chat-shaped text for the first overfit experiment.
- `every-effort-expanded`: a small phrase ladder with more variation.
- `learning-dialogues`: a medium chat-shaped teaching dataset.
- `the-verdict`: larger raw text downloaded to `data/external/the-verdict.txt`.
- `instruction-following`: Chapter 7 instruction data downloaded to `data/external/instruction-data.json`.

Dataset metadata comes from:

```cmd
curl -s http://127.0.0.1:8000/training/datasets
```

## Run Raw Text Training on The Verdict

The Verdict should use the tiny from-scratch model unless you are intentionally experimenting beyond this lesson:

```cmd
curl -s -X POST http://127.0.0.1:8000/training/jobs ^
  -H "Content-Type: application/json" ^
  -d "{\"dataset_id\":\"the-verdict\",\"base_model_id\":\"random-tiny-byte\",\"output_model_id\":\"trained-verdict-byte\",\"max_steps\":320,\"eval_every\":40,\"batch_size\":4,\"block_size\":64,\"learning_rate\":0.003,\"sample_prompt\":\"I had always thought Jack Gisburn\",\"load_when_complete\":true}"
```

This records an experiment where the model learns raw continuation behavior from a larger text.

## Run GPT-2 Instruction SFT

Load GPT-2 first:

```cmd
for /f %i in ('curl -s -X POST http://127.0.0.1:8000/pretrained/jobs -H "Content-Type: application/json" -d "{\"model_size\":\"124M\",\"model_id\":\"gpt2-124M\"}" ^| python -c "import sys,json; print(json.load(sys.stdin)['job_id'])"') do set GPT2_JOB_ID=%i
```

Then use the instruction dataset:

```cmd
curl -s -X POST http://127.0.0.1:8000/training/jobs ^
  -H "Content-Type: application/json" ^
  -d "{\"dataset_id\":\"instruction-following\",\"base_model_id\":\"gpt2-124M\",\"output_model_id\":\"gpt2-instruct-finetuned\",\"max_steps\":20,\"eval_every\":5,\"batch_size\":1,\"block_size\":256,\"learning_rate\":0.00005,\"sample_prompt\":\"Explain what a model checkpoint is in one sentence.\",\"load_when_complete\":true}"
```

This is the experiment that compares raw pretrained GPT-2 with instruction-tuned GPT-2.

## Prompt Roles

- `comparison_prompt`: the prompt used for before/after samples.
- `dataset_probe_prompt`: a representative prompt or phrase for inspecting dataset-specific behavior.
- `prompt_style`: how the backend wraps the prompt before tokenization.

Prompt styles:

- `chat`: `User: ... Assistant:` for tiny chat-shaped datasets.
- `raw`: plain text continuation for The Verdict.
- `instruction`: Chapter 7 instruction template for GPT-2.

## What Before Means

`Before (base)` is generated by the selected `base_model_id` before the current training job updates weights.

- For `random-tiny-byte`, it is the tiny randomly initialized model.
- For `gpt2-124M`, it is downloaded pretrained GPT-2 with instruction prompt formatting.
- For a checkpoint, it is that checkpoint before the next training run.

## Experiment Records

Each record stores dataset ID, training objective, prompt style, base model, output model, loss snapshots, tokens seen, before/after samples, and the checkpoint ID.

The checkpoint stores the full `model.state_dict()`, not only differences.
